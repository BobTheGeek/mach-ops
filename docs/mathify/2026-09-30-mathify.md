## Project profile

Mach Ops: Weapons-Grade Math is a browser arcade flight game (Phaser 3.90 + TypeScript 5.5 + Vite 5, 1280x720, Chromebook target) that teaches FSD Honors Math 7 to one 7th-grade player through 98 sorties across 10 chapters; the player locks bogeys by answering seeded problems. All state lives in one localStorage key (`machops.save.v1`, src/game/save.ts); there is no server, no database, and a hard determinism rule (no Math.random; seeded mulberry32 + FNV-1a, src/engine/rng.ts). The data that exists is the attempt log — skill, tier, correct, responseMs, hintsUsed, context, errorTag, firstTry, ts (src/engine/types.ts:149) — growing at 6-12 rows per sortie, hundreds to a few thousand over months across 83 skills, plus the save file's tiers, records, missionBests and recentHashes. The math already in use is unusually deep: a weighted mastery score with a 10-attempt window (src/engine/mastery.ts), spaced repetition (src/engine/scheduler.ts), a 50/30/20 queue with deinterleaving (src/engine/queue.ts), Little's Law pacing (src/engine/pacing.ts), exact rational curriculum arithmetic (src/engine/stats.ts and friends), seeded Perlin+fbm terrain (src/game/noise.ts), and a pure parent report (src/dad/report.ts). UI surfaces are the game scenes (title, hangar, briefing, sortie, debrief, shop, manual) and the plain-DOM parent view with its heat map, schedule, activity, credits and CSV export.

## Recommendations

### 1. Bayesian inference for rates — Wilson lower bound on the parent heat map (catalog #26)

- **Where:** `src/dad/report.ts:130`, `src/dad/report.ts:165`, `src/dad/report.ts:246`, `src/dad/main.ts:99`
- **Opportunity:** The heat map classifies every skill from a bare first-try percentage with no interval and no minimum-sample guard, so one answered question paints a skill solid green "strong". Classify from a Wilson lower bound instead, show `k of n` beside the percentage, and let low-sample rows read as tentative.
- **Baseline today:** `heatOf` is a point estimate: `if (accuracy >= STRONG_AT) return "strong";` (src/dad/report.ts:130) applied to `Math.round((firstTryCorrect / firsts.length) * 100)` (src/dad/report.ts:165), and a skill enters the first-try basis on one flagged answer (`if (firsts.length > 0)`, src/dad/report.ts:163). The test at tests/dad/report.test.ts:121-136 builds 1 correct first try of 1 and asserts `row.accuracy` is 100 and `row.heat` is `"strong"` — the n=1 regime is encoded as intended behaviour. The chapter header compounds it by averaging per-skill percentages (src/dad/report.ts:246, shown at src/dad/main.ts:197), so one 1-of-1 row moves a chapter figure 100 points. The cost artifact is that same test plus the raw counts that already ship in the CSV but reach the on-screen row only through a per-row hover tooltip (src/dad/main.ts:113-122), so a parent cannot tell a 1-answer green from a 16-answer green without hovering 83 rows. The engine itself does not treat one answer as mastery — `stateFor` needs 10 attempts and 2 correct transfer problems (src/engine/mastery.ts:133,143) — and the two judgment gates disagree about the same skill.
- **User or business impact:** `Medium`. The parent view is the one surface an adult reads and acts on; a solid `Strong 85%+` tile for a skill that has been answered once is a confidence the data do not support, and the flagged side has the same failure (one early miss paints hard orange "flagged" — the state most likely to trigger a reaction at home). Showing the interval and the count makes the page honest at a glance.
- **Effort:** `S` — one closed-form function (~10 lines), a minimum-sample guard, and a test update; no dependency, no data model change (every field already exists).
- **Approach:** Add `wilsonLower(k, n, z = 1.96)` to `src/dad/report.ts` — `p = k/n`, then `(p + z²/2n − z·√(p(1−p)/n + z²/4n²)) / (1 + z²/n)`, returning 0 for n = 0. `buildRow` already has `firstTryCorrect`/`firstTries` (src/dad/report.ts:188,199); expose `accuracyLower` and a `tentative` flag, add `MIN_N_FOR_HEAT` (5 first tries) so loose rows cap at `steady`, and classify `heatOf` from the lower bound. Pool the chapter figure from summed counts instead of the mean-of-percentages at src/dad/report.ts:246. In `src/dad/main.ts:99` print `k/n` beside the percentage and add a low-sample line to `heatTitle`; add the bound and counts to `CSV_HEADER` (counts already there, src/dad/report.ts:307). Update the assertion at tests/dad/report.test.ts:135 (n=1 is tentative) and pin boundary cases for n = 0, 1, 5. Data: `Attempt.firstTry` and `Attempt.correct` (booleans, src/engine/types.ts:152,170) in `SaveFile.log` (src/game/save.ts:52-53), volume per skill 1-16 first tries — the estimate basis is the 6-12 problems per sortie (src/data/campaign.ts missions) times a term of sorties (schedule.json quarters ≈ 9 weeks each), so early-chapter skills sit exactly at n = 1-3.
